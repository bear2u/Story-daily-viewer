# 기획서: Train An Imaginative Agent

## 판단

- 유형: 해결형 (근거: 행동 전에 결과 이미지를 만들고 그 위에서 계획하는 Agima를 제안함, F6-F8)
- 날짜 기준: arXiv 최초 공개
- 독자 친숙도: 생소함. 소코반의 되돌릴 수 없는 한 번 밀기 장면으로 시작함
- 지금 사회에서 어디쯤 와 있나: 프리프린트 공개 이틀째이고 코드·체크포인트·데이터는 공개됐으나 실제 배치와 독립 재현은 아직 확인되지 않음 (W1-W4, L6)
- 도입 질문: AI가 버튼을 누르기 전에 결과 장면을 머릿속으로 그려 보면 실수를 피할 수 있음? → 답은 파트 13에서
- 마지막 답: 네 시뮬레이션에서는 도움이 됐지만, 그 그림은 완벽한 미래가 아니라 행동 선택에 쓰는 불완전한 내부 관측임
- 맺음: 2026-10-21 기준 코드·체크포인트 공개 (W3) / 앞으로 독립 재현과 현실 환경 검증이 필요함 (F39-F44)
- 기대 vs 결과: 더 오래 상상해야 좋아질 것 같지만 RL 뒤 성공률은 오르고 평균 상상 행동 수는 줄었음 (F37-F38)

## 척추

- 마디: 실행 뒤 피드백 | 기존 에이전트는 행동 후에야 결과를 봄 | 전작: I2A는 학습된 환경 롤아웃을 정책의 추가 문맥으로 사용 | 이번: 예측 이미지를 다음 행동의 관측으로 직접 되먹임 | L1-L2 F7
- 마디: 이미지 속 계획 | 한 모델이 행동과 결과 이미지를 번갈아 생성 | 전작: BAGEL이 이미지·텍스트 통합 생성 기반 제공 | 이번: 선형·분기·전방 사고를 같은 문맥에서 수행 | L3 F6-F9
- 마디: 상상을 실제로 씀 | 예측 프레임이 장식인지 검증해야 함 | 전작: 가까운 연구는 텍스트 상태 예측이나 단일 경로 | 이번: Blank/Stale/Oracle 교체 실험으로 내용 의존 확인 | L4 F14-F15
- 마디: 필요한 만큼만 상상 | 고정 형식을 넘어서 언제·어디서 상상할지 학습 | 전작: SFT가 형식을 지정 | 이번: 이진 성공 보상만으로 통합 형식·중요 분기 출현 | F16-F26 F36-F38
- 대가·남은 의문: 틀린 미래 | 내부 그림이 실제 실행과 어긋날 수 있고 시간·FLOPs·현실 배치를 측정하지 않음 | 회수: 공개 코드의 독립 재현과 현실 환경 검증 | F39-F44 W3-W4

## 밑밥과 회수

- 40% 대 2%를 먼저 보여주되 K=5 조건은 바로 밝힘 (파트 2) → Blank/Stale·Oracle 교체가 왜 그런지 회수 (파트 8)
- 더 많이 상상하면 더 좋을 것 같다는 기대 (파트 6) → 성공률 상승과 상상 행동 감소로 회수 (파트 11)
- 성공이라고 말해도 실제로 틀릴 수 있음 (파트 10) → 실패 사례와 현실 적용 한계로 회수 (파트 12)

## 재료

- 재미: 40% 대 2% 격차(F11), 실패 때만 두 번째 계획을 여는 새 형식(F23-F24), 성공률 상승과 상상량 감소(F37-F38), 성공 판정과 실제 실행 불일치(F41-F42)
- 전문성: K 정의(F10), 4개 환경과 easy-to-hard 설정(F27-F30), 통제 기준선(F11-F15), SFT/RL 조건(F16-F17 F21 F34-F35), ablation(F14-F15), 비용 미측정(F39)
- 결정적 증거: 예측 프레임을 Blank/Stale/Oracle로 교체한 Table 2 (F14-F15)
- 구체 예시·비유: 되돌릴 수 없는 소코반 밀기 → html_fig1_1.png; 가까운 먹이부터 먹고 잡히는 팩맨 → html_fig3_1.png; RL 전후 형식 → html_fig5_1.png; 틀린 성공 판정 → html_fig33_1.png
- 전문가용 파트: 7
- 비약 지점: 이미지 생성이 곧 계획은 아님 → 예측 이미지가 다음 행동 입력으로 되먹임되는 구조(F7); RL이 이미지 생성기를 직접 고친다고 오해 가능 → 언어 토큰만 직접 최적화(F16)
- 뺀 것: 후속 피인용 수는 조회 API가 새 논문을 안정적으로 찾지 못해 수치로 쓰지 않음. 실제 서비스 성능과 추론 비용은 논문이 측정하지 않아 쓰지 않음
